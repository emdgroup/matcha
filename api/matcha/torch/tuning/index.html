Hyperparameter optimization function for MATCHA models.

It first runs a QMC scan across different architecture configurations. Then, it runs bayesian optimization via TPE on the parameters of the learning rate. Each trial runs with early stopping to terminate underperforming runs.

The procedure was adapted from here: https://github.com/google-research/tuning_playbook

Parameters:

  • train_set (tuple) – training set to use for hparam scan, should be the output of the correct featurizer

  • val_set (tuple) – validation set to improve on (ideally time split), should be the output of the correct featurizer using is_training=False

  • model_architecture (str) – name of the model to optimize, or model to use for tuning (useful for pretrained ones)

  • model_params (dict) – custom params to keep fixed during the process, a typical example would be in case extra features are used one has to specify additional_mol_features_dim

  • optimizer (str) – which optimizer to use for model training and for tuning its hparams, defaults to “adam”

  • num_epochs (int) – max number of epochs to use, defaults to 200

  • patience (int) – how many epochs to wait before early stopping, defaults to 20

  • stochastic_weight_averaging (bool) – whether to use SWA

  • accelerator (str) – whether to train on cpu or gpu, defaults to “gpu”

  • architecture_search_budget (int) – how many QMC sampling iterations to do for the architecture search step, defaults to 70

  • architecture_grid (dict | None) – which params to change for the given architecture, defaults to None, meaning it will be loaded from architecture_grid.json

  • optimizer_search_budget (int) – How many TPE steps to do when tuning the learning rate parameters, defaults to 30

  • optimizer_grid (dict | None) – which params to tune for the optimizer, defaults to None, meaning it will be loaded from optimizer_grid.json

  • scheduler_grid (dict | None) – search space for scheduler parameters to tune in Phase 2, defaults to None, meaning it will be loaded from scheduler_grid.json based on the active scheduler

  • logging_uri (str | None) – MLflow tracking URI for logging trials. If None, logging is disabled.

  • study_name_arc (str) – Optuna study name for the architecture search phase.

  • study_name_opt (str) – Optuna study name for the optimizer search phase.

Returns:

dictionary with keys "optimum" (best params), "architecture" (Optuna study or "Not executed"), and "optimizer" (Optuna study or "Not executed").
